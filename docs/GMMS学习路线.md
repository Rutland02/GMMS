# GMMS 学习路线

这条路线面向从 C++ 初学者到能够独立维护 GMMS 的学习者。建议每周投入 6～10 小时，完整周期约 8～12 周。学习时间较少时，可以将每个阶段延长一倍。

## 0. 开始前：准备环境

### 目标

- 能够打开 Qt Creator。
- 能够构建并运行 GMMS。
- 知道源码目录、构建目录和运行数据的区别。

### 要学的内容

- 编译器、Qt Kit、qmake 的基本概念
- `.h`、`.cpp`、`.pro` 文件的作用
- 工作目录和 `gym_data.json` 的位置
- Git 仓库与 `.gitignore`

### 通过标准

- 可以成功运行主窗口。
- 可以新增一个会员并关闭程序。
- 重新打开程序后，知道如何检查数据是否被保存。

## 1. C++ 语法基础：1～2 周

### 学习内容

- 变量和基本类型
- 字符串、条件语句和循环
- 函数、参数和返回值
- 指针、引用和 `const`
- 结构体与类
- 构造函数和初始化列表
- 头文件与源文件

### 对应项目

- `model/member.h/.cpp`
- `model/course.h/.cpp`
- `model/checkin.h/.cpp`

### 练习顺序

1. 不看代码写一个简单的 `Member` 类。
2. 为它增加 getter 和 setter。
3. 增加 `addPoints` 和 `reducePoints`。
4. 增加判断会员是否过期的函数。
5. 使用 `QVector<Member>` 保存三个会员。

### 阶段成果

能够独立解释以下代码：

```cpp
QString name() const;
void setName(const QString& name);
```

## 2. 面向对象与数据建模：1 周

### 学习内容

- 封装
- 对象的职责
- 类之间的关系
- 值对象和实体对象的区别
- 为什么不应该让 UI 直接修改成员变量

### 对应项目

```text
Member   → 会员
Course   → 课程
CheckIn  → 预约/签到记录
```

### 练习

- 为每个类画属性和方法表。
- 找出每个类不应该负责的工作。
- 讨论“等级是否应该由积分自动决定”。
- 阅读当前课程 ID 关联记录的实现，并写出旧记录兼容回退的设计草图。

### 阶段成果

能够从一段自然语言需求中识别类、属性和行为。

## 3. Qt 入门：1～2 周

### 学习内容

- `QApplication`
- `QWidget` 和 `QMainWindow`
- 控件创建
- 布局管理器
- Qt 对象父子关系
- 信号与槽

### 对应项目

- `main.cpp`
- `ui/gymmainwindow.h/.cpp`

### 练习顺序

1. 在主窗口中增加一个按钮。
2. 点击按钮后弹出提示框。
3. 增加一个输入框并读取文本。
4. 将输入内容显示到标签上。
5. 增加一个新的空白标签页。
6. 切换浅色和深色主题。

### 阶段成果

能够独立创建一个包含按钮、输入框、标签和表格的简单窗口。

## 4. Qt 表格与数据展示：1 周

### 学习内容

- `QTableWidget`
- 表头和行列
- `QTableWidgetItem`
- 表格刷新
- 表格选中行
- 表格排序和筛选的风险

### 对应项目

- `ui/membertab.cpp`
- `ui/coursetab.cpp`
- `ui/bookingtab.cpp`

### 练习

- 将会员数据显示到表格。
- 点击表格行后填充编辑表单。
- 增加课程名称搜索。
- 观察搜索后直接使用 `currentRow()` 可能造成的错误。
- 使用 `Qt::UserRole` 在表格项中保存业务 ID。

### 阶段成果

理解“显示行号”和“真实数据对象 ID”不是同一个概念。

## 5. 业务逻辑与数据中心：1～2 周

### 学习内容

- CRUD
- 业务规则
- 错误返回
- 信号通知
- 数据中心与界面解耦

### 对应项目

- `core/gymdata.h/.cpp`
- `ui/bookingtab.cpp`

### 学习顺序

1. 读懂添加、编辑、删除会员。
2. 读懂添加、编辑、删除课程。
3. 逐行分析预约流程。
4. 逐行分析签到流程。
5. 为每个失败分支写一个测试场景。
6. 将整数索引接口逐步改为 ID 接口。

### 已完成的基线改进

- 预约和课程编辑/删除改为按会员卡号或课程 ID 操作。
- 课程搜索后编辑和删除不会再误操作原始列表中的同一行。
- 课程 ID 改为基于当前最大编号生成。
- 课程容量是硬上限，统计页面排除过期课程。
- 预约和签到记录保存课程 ID，同时兼容旧 JSON 记录。

### 必做改进练习

- 明确会员等级的唯一来源，消除手动等级和积分自动升级的规则冲突。
- 用 `enum class` 替代业务字符串。
- 为预约容量、重复预约和记录关联增加测试。

### 阶段成果

能够把一个业务需求拆成“检查条件—修改数据—通知界面”的完整流程。

## 6. JSON 文件与持久化：1 周

### 学习内容

- 文件打开、读取和关闭
- `QJsonDocument`
- `QJsonObject`
- `QJsonArray`
- 日期和时间序列化
- 解析错误和数据校验

### 对应项目

- `GymData::saveToJson`
- `GymData::loadFromJson`
- `GymMainWindow::closeEvent`

### 练习

1. 修改一个会员后检查 JSON 内容。
2. 删除一个字段，观察加载结果。
3. 输入错误日期，补充校验。
4. 增加 JSON 版本字段。
5. 将加载流程改成“临时数据全部成功后再替换”。
6. 设计自动保存或备份文件方案。

### 阶段成果

能够将一个简单 C++ 类手动转换为 JSON，并从 JSON 恢复对象。

## 7. 查询、导出和统计：1 周

### 学习内容

- 字符串匹配
- 日期范围筛选
- `QMap` 聚合
- CSV 格式
- Qt Charts 基本概念

### 对应项目

- `ui/querytab.cpp`
- `ui/statisticstab.cpp`

### 练习

- 增加按会员 ID 查询。
- 增加按课程类型统计。
- 增加每日签到人数统计。
- 阅读并验证当前 CSV 的逗号、引号、换行转义和中文编码处理。
- 增加会员活跃度排行。

### 阶段成果

能够把一组记录转换为表格、统计结果和图表。

## 8. 测试与调试：1 周

### 学习内容

- 正常路径测试
- 边界测试
- 错误输入测试
- 日志和断点调试
- 回归测试

### 测试顺序

1. 空输入。
2. 重复 ID。
3. 过期会员和课程。
4. 满员课程。
5. 重复预约和重复签到。
6. 删除数据后再次新增。
7. 搜索、排序后编辑和删除。
8. 非法 JSON。
9. 保存失败、重试和放弃保存。

### 阶段成果

能够写出一份测试清单，并根据测试结果定位是界面、业务还是数据问题。

## 9. 重构与工程化：1～2 周

### 学习内容

- `enum class`
- `constexpr`
- 按 ID 操作数据
- Model/View
- 独立对话框类
- 自动化测试
- CMake 或规范化 qmake
- Git 提交和版本说明

### 推荐重构顺序

1. 集中管理等级、记录类型和积分常量。
2. 将业务字符串改为枚举。
3. 已将界面行号改为业务 ID；继续补充相关自动化测试。
4. 提取会员编辑和课程编辑对话框。
5. 为 `GymData` 核心逻辑增加测试。
6. 将 `QTableWidget` 逐步替换为 Model/View。
7. 视需求将 JSON 迁移为 SQLite。

### 阶段成果

能够解释“为什么要重构”，并能用小步提交保证每次改动都可验证。

## 10. 每周学习模板

每周可以采用以下节奏：

| 时间 | 活动 |
|---|---|
| 第 1 天 | 阅读本章概念和对应源码 |
| 第 2 天 | 手动运行功能，记录现象 |
| 第 3 天 | 独立完成一个小练习 |
| 第 4 天 | 修改项目并观察结果 |
| 第 5 天 | 设计边界测试 |
| 第 6 天 | 整理笔记、提交 Git |
| 第 7 天 | 复盘并回答本章问题 |

不要只复制代码。每个阶段都应该完成“读懂—运行—修改—测试—总结”五步。

## 11. 学习检查点

### 初级检查点

- 能解释 `main.cpp` 做了什么。
- 能创建一个 `Member` 对象。
- 能找到会员数据存储在哪里。
- 能找到预约业务的入口。
- 能说出 JSON 文件什么时候被读写。

### 中级检查点

- 能新增一个会员字段并显示到表格。
- 能新增一个课程字段并保存到 JSON。
- 能增加一个查询条件。
- 能为一个业务规则写测试。
- 能发现并修复搜索后编辑错误对象的问题。

### 高级检查点

- 能将业务操作改成按 ID 处理。
- 能解释 UI、业务和持久化之间的依赖关系。
- 能提出并实施一次有测试保护的重构。
- 能为项目写出清晰的构建、使用和扩展文档。

## 12. 学完之后的扩展路线

完成 GMMS 后，建议按以下方向继续：

```text
C++ 基础
  → Qt Widgets
  → Model/View
  → JSON 与文件系统
  → SQLite 与数据库设计
  → 单元测试
  → CMake 与 CI
  → 更大型的桌面或服务端项目
```

可以尝试的扩展项目包括：

- 健身房收银和会员续费
- 教练排班系统
- 课程取消和退费
- 预约名额释放
- 多管理员登录
- SQLite 数据库版本
- REST API 服务端版本
- Qt Quick/QML 移动端界面

## 13. 最终学习成果

完成这条路线后，学习者不只是“会运行一个 Qt 项目”，而应该能够：

- 看懂一个中小型 C++/Qt 项目的结构。
- 根据需求增加一个完整功能。
- 找到并修复常见的业务逻辑错误。
- 设计基本的数据模型和持久化方案。
- 使用 Git 保存可回退、可说明的开发过程。
- 从能运行的代码继续改进为更可靠、更易维护的代码。
