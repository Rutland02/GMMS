# GMMS 健身房会员管理系统：C++/Qt 教材案例

## 1. 案例定位

GMMS（Gym Member Management System）是一个基于 C++、Qt Widgets 和 JSON 文件的健身房会员管理系统。

本案例不把重点放在“记住多少 Qt 类”上，而是通过一个完整的小型桌面应用，带领学习者经历以下过程：

```text
需求分析 → 数据建模 → 业务规则 → 图形界面 → 文件持久化 → 统计分析 → 测试与重构
```

适合：

- 已经接触过基础 C++ 语法，准备做第一个完整项目的人
- 想学习 Qt Widgets 桌面开发的初学者
- 需要一个面向对象、文件读写和 GUI 综合练习的课程项目

不建议完全没有编程经验的人直接阅读全部代码。零基础学习者应先完成文末的学习路线，再按章节逐步进入项目。

## 2. 案例学习目标

完成本案例后，学习者应该能够：

1. 使用 C++ 类描述会员、课程和操作记录等现实对象。
2. 理解头文件、源文件、构造函数、封装、`const`、引用和容器。
3. 使用 Qt Widgets 创建窗口、布局、表格、对话框和标签页。
4. 使用 Qt 信号与槽响应按钮、输入框和数据变化。
5. 将界面层、业务层和数据模型进行基本分离。
6. 使用 `QVector`、`QMap`、`QString`、`QDate` 和 `QDateTime` 处理数据。
7. 使用 JSON 文件保存和恢复程序数据。
8. 实现搜索、筛选、CSV 导出和基础统计图表。
9. 通过边界测试发现并修复真实项目中的逻辑问题。
10. 使用 Git 管理源码，避免提交 IDE 配置和编译产物。

## 3. 案例背景与需求

### 3.1 业务背景

健身房需要维护会员信息和课程信息，并记录会员的预约与签到行为。管理员希望通过桌面软件完成日常操作，并查看会员活跃度和课程使用情况。

### 3.2 核心对象

| 对象 | 主要信息 | 主要行为 |
|---|---|---|
| 会员 `Member` | 卡号、姓名、有效期、等级、积分 | 增加积分、减少积分、判断过期、等级检查 |
| 课程 `Course` | ID、名称、类型、教练、时间、价格、人数、有效期 | 判断满员、判断有效期、解析时间 |
| 记录 `CheckIn` | 会员、课程、时间、记录类型 | 保存预约或签到事实 |
| 数据中心 `GymData` | 会员、课程、记录集合 | 增删改、预约、签到、保存、加载、统计 |

### 3.3 功能需求

系统包含五个标签页：

1. **会员管理**：注册、编辑、删除会员，调整积分并显示等级。
2. **课程管理**：发布、编辑、删除、搜索课程，显示人数和状态。
3. **预约与签到**：选择会员和课程，执行预约或签到，查看近期记录。操作使用会员卡号和课程 ID，而不是依赖下拉框的显示行号。
4. **数据记录**：按类型、时间和关键词筛选记录，并导出 CSV。
5. **数据统计**：查看会员、课程、积分、预约、签到和每日活动趋势。

### 3.4 当前规则

当前基线代码中的规则如下，学习时应先读懂，再讨论是否合理：

- 预约成功增加 5 积分。
- 签到成功增加 10 积分。
- 积分达到 500、2000、5000 时，等级自动变为白银、黄金、钻石。
- 会员卡过期后不能预约或签到。
- 过期课程不能预约或签到。
- 同一会员不能重复预约同一课程，也不能重复签到同一课程。
- 普通、黄金、钻石会员的同时预约数量不同。
- 课程容量是硬上限，会员等级不再突破课程最大人数。

> 教学提醒：当前代码将会员等级既作为界面可编辑字段，又作为积分自动计算结果。这个设计存在规则冲突，适合作为“需求澄清与重构”练习，而不是最终业务标准。

## 4. 技术栈与运行方式

### 4.1 技术栈

- C++17
- Qt Widgets
- Qt Charts
- qmake
- JSON 文件存储
- Windows + Qt/MinGW（原项目开发环境）

工程文件位于 `GymManagerComplete(GMMS2.0)/GymManager.pro`。

### 4.2 构建步骤

1. 安装 Qt，并确保包含 Qt Widgets、Qt Charts 和对应 C++ 编译器。
2. 使用 Qt Creator 打开 `GymManager.pro`。
3. 选择可用的 Qt Kit。
4. 构建并运行项目。
5. 程序会在当前工作目录读取或创建 `gym_data.json`。

项目仓库通过 `.gitignore` 忽略 `gym_data.json`、`release/`、`.o`、`.exe` 等本地文件。这样可以避免个人运行数据和构建产物进入 Git。

## 6. 分章教学内容

### 第 1 章：从需求到对象

**学习目标**

- 把现实需求转换为程序对象。
- 区分“数据”与“行为”。
- 理解为什么要拆出 `Member`、`Course` 和 `CheckIn`。

**阅读文件**

- `model/member.h`
- `model/course.h`
- `model/checkin.h`

**课堂任务**

1. 画出三个类的属性表。
2. 找出每个类的构造函数、读取函数和修改函数。
3. 解释 `isExpired()`、`isFull()` 为什么应该属于模型类。

**练习**

- 为会员增加手机号字段。
- 为课程增加教室字段。
- 为签到记录增加备注字段。

**完成标准**

学习者能够不看资料写出一个带构造函数和 getter/setter 的简单 `Member` 类。

### 第 2 章：C++ 文件、类和容器

**学习目标**

- 理解 `.h` 与 `.cpp` 的职责。
- 掌握初始化列表、`const` 成员函数和引用返回值。
- 使用 `QVector` 保存多个对象。

**阅读重点**

```cpp
const QVector<Member>& getMembers() const;
```

需要回答：

- 为什么返回 `const` 引用？
- 如果返回值而不是引用会怎样？
- 为什么调用方不能直接修改返回结果？

**练习**

- 编写函数统计会员总数。
- 编写函数查找积分最高的会员。
- 使用范围 `for` 循环输出所有课程名称。

### 第 3 章：数据中心与 CRUD

**学习目标**

- 理解 `GymData` 的作用。
- 完成会员和课程的增删改查。
- 认识唯一 ID 和重复数据检查。

**阅读文件**

- `core/gymdata.h`
- `core/gymdata.cpp` 中的 `addMember`、`editMember`、`deleteMember`、`addCourse` 等函数。

**课堂任务**

画出以下调用链：

```text
点击“注册会员”
  → MemberTab 的 lambda
  → GymData::addMember
  → 检查卡号
  → 写入 QVector
  → 发出 dataChanged
  → 页面 refresh
```

**练习**

- 增加按卡号查找会员的函数。
- 增加按课程 ID 查找课程的函数。
- 将编辑和删除接口从“按下标”改为“按 ID”。

> 这是本案例的重要重构任务。表格可以排序或过滤，因此业务层不应该依赖 UI 行号。

### 第 4 章：Qt 窗口、布局和标签页

**学习目标**

- 创建 `QApplication` 和主窗口。
- 使用布局管理器组织控件。
- 使用 `QTabWidget` 组合多个功能页面。

**阅读文件**

- `main.cpp`
- `ui/gymmainwindow.h/.cpp`

**重点概念**

- Qt 对象树和父子关系
- `QWidget` 与 `QMainWindow`
- `QVBoxLayout`、`QHBoxLayout`、`QFormLayout`
- 前向声明和指针成员

**练习**

- 增加一个“关于本程序”按钮。
- 在主窗口顶部显示当前日期。
- 为主窗口增加状态栏消息。

### 第 5 章：信号与槽驱动界面

**学习目标**

- 理解事件驱动程序。
- 连接按钮点击和页面刷新。
- 理解 `dataChanged` 信号的作用。

**阅读重点**

```cpp
connect(data, &GymData::dataChanged,
        this, &MemberTab::refresh);
```

**练习**

- 新增会员后自动切换到会员标签页。
- 数据改变时更新窗口标题。
- 为保存成功和失败分别发送不同提示。

### 第 6 章：业务规则——预约与签到

**学习目标**

- 把业务流程拆成检查步骤。
- 理解失败原因和用户提示。
- 学习如何避免重复预约和重复签到。

**阅读文件**

- `ui/bookingtab.cpp`
- `core/gymdata.cpp` 中的 `bookCourse` 和 `checkIn`

**建议先画流程图**

```text
选择会员和课程
  ↓
索引/ID 是否有效？
  ↓
会员或课程是否过期？
  ↓
是否重复操作？
  ↓
是否超过容量或等级限制？
  ↓
修改预约人数、积分和记录
  ↓
发送 dataChanged
```

**已完成的基线改进与练习**

1. 课程搜索后的编辑/删除已改为依据课程 ID 操作。
2. 课程 ID 已改为取当前最大编号加一，避免删除中间课程后的冲突。
3. 预约和签到记录已保存课程 ID，并兼容旧记录的课程名称回退。
4. 已将课程容量设为硬上限；钻石会员特权只影响个人预约数量。
5. 继续练习：明确会员等级的唯一来源，并为预约容量规则编写测试。

### 第 7 章：JSON 持久化

**学习目标**

- 将 C++ 对象转换为 JSON。
- 从 JSON 恢复对象。
- 处理文件不存在、格式错误和字段缺失。

**阅读文件**

- `core/gymdata.cpp` 中的 `saveToJson`
- `core/gymdata.cpp` 中的 `loadFromJson`
- `ui/gymmainwindow.cpp` 中的启动加载和关闭保存

**当前实现与推荐改进**

- 当前实现使用 `QJsonParseError` 检查格式，并验证核心字段、日期、数值和重复 ID。
- 当前实现先加载到临时容器，全部成功后再替换正式数据。
- 当前实现使用 `QSaveFile` 原子写入，降低中途失败导致数据损坏的风险。
- 当前实现保存失败时提供重试或放弃保存的选择。
- 继续练习：将具体解析错误传递到界面，并增加 JSON 版本迁移机制。

**练习**

- 手动删除一个 JSON 字段，观察程序行为。
- 将日期改成非法格式，增加错误提示。
- 编写 JSON 版本字段，例如 `"version": 1`。

### 第 8 章：查询、导出与统计

**学习目标**

- 按类型、日期和关键词筛选记录。
- 使用 `QTextStream` 导出 CSV。
- 使用 `QMap` 聚合统计数据。
- 使用 Qt Charts 绘制趋势图。

**阅读文件**

- `ui/querytab.cpp`
- `ui/statisticstab.cpp`
- `core/gymdata.cpp` 中的统计函数

**练习**

- 增加按会员 ID 筛选。
- 增加“仅显示有效课程”选项。
- 当前实现已处理 CSV 中的逗号、换行和引号，并写入 UTF-8 BOM 以改善中文软件兼容性。
- 继续练习：导出前增加字段选择和文件覆盖确认。
- 增加按会员统计签到次数。
- 增加预约转化率或课程使用率指标。

### 第 9 章：测试、调试与重构

**学习目标**

- 用边界情况检验业务规则。
- 将问题分为 UI 问题、业务问题和数据问题。
- 通过小步重构改善代码，而不是一次性推翻项目。

**最低测试清单**

| 测试场景 | 预期结果 |
|---|---|
| 添加重复会员卡号 | 添加失败 |
| 添加重复课程 ID | 添加失败 |
| 过期会员预约 | 预约失败 |
| 过期课程预约 | 预约失败 |
| 重复预约同一课程 | 预约失败 |
| 未预约直接签到 | 按规则失败 |
| 积分达到等级阈值 | 等级正确变化 |
| 删除课程后添加新课程 | ID 不冲突 |
| 搜索后编辑课程 | 编辑搜索到的课程 |
| JSON 格式错误 | 给出错误，不覆盖有效内存数据 |

**期末重构目标**

- 用 `enum class` 替代“预约”“签到”“普通”等业务魔法字符串。
- 用 `constexpr` 集中管理积分奖励和等级阈值。
- 已使用会员卡号和课程 ID 替代界面行号进行对象操作。
- 将课程编辑窗口提取为独立的 `CourseDialog` 类。
- 为 `GymData` 的核心业务函数增加自动化测试。

## 7. 建议的最终架构

初始项目的结构适合入门。完成改进后，可以逐步演进为：

```text
ui/
  只负责控件、输入和显示
service/
  负责预约、签到、会员规则
repository/
  负责 JSON 或数据库读写
model/
  负责领域对象和值
statistics/
  负责统计计算
```

不要求初学者一开始就采用复杂架构。正确的学习方式是：先让当前版本跑起来，再针对具体问题进行小步重构。

## 10. 学习时的正确心态

本项目的价值不在于每一行代码都完美，而在于它提供了一个可以运行、可以阅读、可以修改、可以发现问题的完整案例。

学习者应同时做三件事：

1. 先理解当前代码为什么能运行。
2. 再主动寻找当前设计的限制。
3. 最后通过小范围修改验证自己的理解。

当你能够说明“这段代码现在能做什么、可能在哪里出错、我准备怎样验证和改进”，就已经从语法学习进入了项目开发学习。
